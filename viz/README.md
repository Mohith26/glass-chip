# glasschip-viz

This is the web view of Glass Chip. On the left a Franka Panda picks parts off a conveyor. On the right a 3D glass model of VX-1, a fictional robot SoC, runs every robot task in simulated time: NoC transfers fly between routers as light trails, NPU tiles light up layer by layer, DRAM controllers show their queue depth, and each power domain is tinted by its voltage. A ring per task counts down to its deadline and flashes red on a miss. Underneath is a Perfetto-style timeline with one track per task and per engine unit.

Every number on screen comes from the loaded replay. Replays generated by `tools/make_dev_replay.py` are synthetic and carry a "Synthetic dev data" badge.

## Run it

```
cd viz
npm install
npm run dev          # http://127.0.0.1:5317
npm run build        # static site in viz/dist (relative paths, works on Cloudflare Pages or GitHub Pages)
npm run lint
```

Dev replays (synthetic):

```
.venv/bin/python tools/make_dev_replay.py          # writes viz/public/replays/* and index.json
.venv/bin/python -m pytest viz/tests               # replay writer round-trip tests
```

URL parameters: `?replay=S2_P0` picks a replay from `replays/index.json`, `?t=6.2` starts at 6.2 s, `?live=ws://host:port` connects to a live co-sim server.

## How to use it

- Space plays and pauses. The speed slider goes from real time down to 1/100,000, where individual transfers crawl across the mesh. The arrow keys step to the previous or next chip event.
- Timeline: drag to pan, pinch or ⌘ scroll to zoom around the cursor, W A S D also work. Click a job to select it; its critical path is outlined on the engine tracks and connected with flow lines. Click the overview strip to jump.
- Click a deadline ring to jump to that task's latest job. On a missed job, "Why did this miss?" animates the critical path through the die and shows the attribution breakdown.
- Scenario buttons and the policy switcher swap between precomputed replays that share a seed, keeping the playhead where it is.
- Metrics opens the drawer: per-task p99 vs deadline and misses, SoC power, energy per robot-hour, temperatures, the latency-tolerance band, and the design-space panel.
- Engineer exports the visible window as a Perfetto (Chrome JSON) trace, exports results JSON, and shows the YAML configs behind the run.
- Guided tour walks through the demo story in about three minutes.

## How it is built

- Vite, TypeScript (strict), Three.js on WebGL2 with an UnrealBloom pass. The two 3D views are separate renderers; the timeline and drawer charts are 2D canvas.
- Replays are chunked by time and gzip compressed. A Web Worker fetches and decodes chunks into typed arrays, so scrubbing never parses on the main thread. The format is in `REPLAY_FORMAT.md`; the Python writer is `tools/replay_writer.py`.
- Transfers are instanced quads animated entirely in the vertex shader along their XY route, so the CPU only rebuilds the instance buffer when the visible time window moves. At fast playback each transfer becomes one particle and the per-link byte counts drive glowing flow ribbons; in slow motion each transfer becomes a stream of particles. I tested 200k particles in flight at 60 fps or better on an Apple Silicon laptop.
- The robot view reads the co-sim scene export (`cosim/SCENE_FORMAT.md`) or, as a fallback, the Panda geometry exported by `scripts/export_panda_scene.py`, and plays back recorded body poses.
- The design-space panel loads an ONNX surrogate with onnxruntime-web when `replays/index.json` lists one. Until then it stays visibly disabled and computes nothing.

## Layout

```
src/main.ts            app shell, interactions, tour host
src/replay/            format types, binary decoders, worker, chunk store
src/live/client.ts     WebSocket + msgpack client sharing the replay decoders
src/views/             robot, die, rings, timeline, drawer
src/ui/                why-did-this-miss card, guided tour, engineer mode
src/dse/surrogate.ts   onnxruntime-web design-space panel
src/palette.ts         task colors shared by every view (Python reads this file too)
```

VX-1 is a fictional reference SoC inspired by public descriptions of physical-AI SoCs. It does not describe any real product.
